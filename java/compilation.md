# Java Compilation

This document describes the basic process of compiling and running Java programs from the command line.

## Compilation process

Java source code is written in files with the `.java` extension.

For example:

```text
MyFirstApp.java
```

The Java compiler (`javac`) compiles the source code into Java bytecode:

```text
MyFirstApp.java
        ↓
      javac
        ↓
MyFirstApp.class
```

The resulting `.class` file contains bytecode that can be executed by the Java Virtual Machine (JVM).

## Compile a Java program

Navigate to the directory containing the Java source file.

For example:

```powershell
cd C:\Users\tommy\Documents\programming\java-learning\head-first-java\chapter-01
```

Compile the source file:

```powershell
javac MyFirstApp.java
```

If compilation succeeds, `javac` normally produces no terminal output.

A new file should appear:

```text
MyFirstApp.class
```

Verify this with:

```powershell
dir
```

## Run a compiled program

Run the program using:

```powershell
java MyFirstApp
```

Use the class name without the `.class` extension.

The JVM loads the bytecode from `MyFirstApp.class` and executes the program.

## Source code versus bytecode

### `.java`

A `.java` file contains human-readable Java source code.

Example:

```java
public class MyFirstApp {
    public static void main(String[] args) {
        System.out.println("Hello, Java!");
    }
}
```

### `.class`

A `.class` file contains compiled Java bytecode.

It is generated by `javac` and should not be edited manually.

## Class Names and Case Sensitivity

Java is case-sensitive. Class names must therefore use exactly the same
capitalization when compiling and running a program.

### Problem

The following error occurred when attempting to run `Exercise1A`:

```text
Error: Could not find or load main class Exercise1A
Caused by: java.lang.NoClassDefFoundError:
Exercise1A (wrong name: Exercise1a)
```

### Cause

The class was named `Exercise1a` in the source code, while the program was
executed using:

```powershell
java Exercise1A
```

Java treats `Exercise1A` and `Exercise1a` as different class names because
identifiers are case-sensitive.

### Relationship Between File and Class Names

When a source file contains a public class, the filename must match the public
class name exactly, including capitalization.

For example:

```java
public class Exercise1A {
    public static void main(String[] args) {
        // Program code
    }
}
```

should be stored as:

```text
Exercise1A.java
```

The program can then be compiled and executed with:

```powershell
javac Exercise1A.java
java Exercise1A
```

The relationship is:

```text
Exercise1A.java
        ↓
public class Exercise1A
        ↓
javac Exercise1A.java
        ↓
Exercise1A.class
        ↓
java Exercise1A
```

### Diagnosis

When Java reports `wrong name`, compare the class name in the source code with
the name used in the `java` command.

Also verify the filename when the class is declared `public`.

Pay particular attention to capitalization.

### Solution

Use the same class name and capitalization consistently in:

* the public class declaration;
* the `.java` filename;
* the `java` command.

After correcting the source code or filename, compile the program again before
running it.

### Key Principle

Java is case-sensitive. `Exercise1A` and `Exercise1a` are different
identifiers.

For a public class, keep the class name, source filename, and name used to run
the program consistent.

## Compile after making changes

After changing the source code, compile the `.java` file again:

```powershell
javac MyFirstApp.java
```

Then run the updated program:

```powershell
java MyFirstApp
```

The basic development cycle is therefore:

```text
Edit source code
      ↓
Save .java file
      ↓
Compile with javac
      ↓
Generate .class file
      ↓
Run with java
      ↓
Inspect output
      ↓
Edit again
```

## Common mistakes

### Running the source filename

When executing a compiled class, use:

```powershell
java MyFirstApp
```

rather than:

```powershell
java MyFirstApp.class
```

### Forgetting to recompile

Changing `MyFirstApp.java` does not automatically update an existing `MyFirstApp.class` when compiling manually.

After editing the source code, run `javac` again.

### Compilation errors

If `javac` reports an error, the `.java` source code contains something the compiler cannot successfully compile.

Read the error message and check the referenced line before trying to run the program.
